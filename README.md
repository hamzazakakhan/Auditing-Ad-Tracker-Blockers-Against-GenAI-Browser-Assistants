Can Privacy Extensions Protect You From Other Extensions? Auditing Ad/Tracker Blockers Against GenAI Browser Assistants
Student: Hamza (2024213)
Project ID: 32104
Summary
GenAI browser assistants (e.g. Sider, Monica, Merlin, MaxAI, Perplexity, Harpa, TinaMind, Copilot, ChatGPT for Google) operate as browser extensions with deep DOM access, allowing them to read and transmit full webpage content — including sensitive data such as Social Security numbers, medical records, and academic grades — primarily to their own first-party servers, with some also sharing chat/user identifiers with third parties like Google Analytics and Mixpanel (USENIX Security 2025, "Big Help or Big Brother?"). That study was conducted on vanilla Chrome with no privacy tooling installed, leaving an open question this project addresses: can a privacy or ad-blocking extension running alongside a GenAI assistant meaningfully reduce its data collection, or is the collection baked into the assistant's own first-party design in a way no blocker can touch?
This project selects three GenAI browser assistants and tests each against three leading privacy/ad-blocking extensions (e.g. uBlock Origin, Privacy Badger, Ghostery) in a controlled environment. Using instrumented browser sessions and network traffic capture (e.g. via mitmproxy/Burp Suite), it measures what data each assistant collects and transmits with no blocker active (baseline), and how that collection changes — if at all — with each privacy extension enabled. Both first-party (assistant's own servers) and third-party (analytics/tracking) exfiltration are measured separately, since blockers are more likely to affect third-party requests than an assistant's own core data pipeline.
Novel Security Problem Addressed
Existing research documents that GenAI browser assistants exfiltrate sensitive page content and identifiers, but has not evaluated whether commonly deployed privacy tooling is capable of mitigating this risk. This creates a gap: users may believe their privacy extensions protect them from assistant-based data collection when in practice the collection may be architecturally immune to blocking (e.g. same-origin requests indistinguishable from legitimate assistant functionality). This project is the first to empirically test whether privacy extensions provide meaningful protection against a different, more privileged class of extension.
Impact of the Proposed Solution
The results will give users and organizations evidence-based guidance on whether relying on ad/tracker blockers is sufficient protection when using GenAI browser assistants, or whether additional controls (e.g. assistant allowlisting, DLP policies, or avoiding certain assistants entirely) are necessary. For extension developers, the findings highlight which collection patterns are currently blockable and which require new detection approaches, informing future privacy-tool design. For policymakers and enterprise security teams, the project provides a reproducible methodology for auditing third-party AI browser tooling before organizational deployment.
